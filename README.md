# Локальная агентская предразметка кадров

Рабочая первая версия программы для предразметки кадров производственной линии. Приложение сканирует локальную папку, последовательно передаёт изображения в Codex CLI, строго проверяет JSON-ответ, создаёт YOLO Segmentation label и контрольное изображение, а затем требует ручного решения оператора.

Ни одна автоматическая аннотация не попадает в экспорт без явного подтверждения.

Полные требования к завершённому продукту, поддержке macOS/Linux/Windows,
режимам `1X/2X`, детальному проходу и графической ручной разметке описаны в
[продуктовой и технической спецификации](docs/PRODUCT_SPECIFICATION.md).

## Возможности

- JPEG, JPG и PNG из `data/incoming`;
- защита от дубликатов по SHA-256;
- неизменяемая контролируемая копия каждого исходника;
- SQLite-очередь с безопасным восстановлением после перезапуска;
- один последовательный worker, timeout и строгий лимит режима `1X/2X`;
- реальный неинтерактивный `codex exec` в `read-only`;
- строгая JSON Schema и повторная Pydantic-валидация;
- геометрические и классовые проверки;
- YOLO Segmentation с координатами `0..1`;
- цветной preview;
- обязательная ручная проверка;
- принятие, отклонение, исправление JSON или повторная обработка;
- повтор с детализацией до четырёх выбранных или автоматических фрагментов;
- полноэкранная ручная разметка мышью с черновиками и undo/redo;
- ZIP только из `approved`-кадров;
- импорт legacy ZIP/папки с отчётом миграции;
- локальный журнал ошибок и CLI-диагностика;
- автоматические unit/integration/E2E-тесты без обращения к OpenAI.

Активные классы экспортируемого датасета:

```text
0 — tray_filled
1 — qr_code
2 — tray_empty
```

`line` читается только при миграции старых данных и не создаётся, не показывается
и не экспортируется.

## Требования

- macOS 12+, Ubuntu 20.04+/Debian 10+ или Windows 11;
- Windows 11 + WSL2 поддерживается как дополнительный Linux-вариант;
- Python 3.11 или новее;
- установленный Codex CLI;
- активная авторизация `codex login`;
- локальный браузер.

Поддерживаются нативные macOS, Linux и Windows. Обычной Ubuntu или Debian WSL2
не требуется.

## Установка на macOS и Linux

```bash
./scripts/setup.sh
codex login
.venv/bin/python -m app doctor
```

Для Windows + WSL2 используйте те же Linux-команды внутри Ubuntu.

Запуск:

```bash
./scripts/run.sh
```

## Установка на нативный Windows 11

Откройте PowerShell в корне проекта:

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\scripts\setup.ps1
codex login
.\.venv\Scripts\python.exe -m app doctor
```

Запуск:

```powershell
.\scripts\run.ps1
```

После запуска на любой платформе откройте
[http://127.0.0.1:8098](http://127.0.0.1:8098). Сервер намеренно не слушает
внешние сетевые интерфейсы.

## Основной сценарий

1. Скопируйте JPEG/PNG в `data/incoming`. Не перемещайте туда единственный экземпляр важного файла.
2. Нажмите «Сканировать папку».
3. Нажмите «Запустить предразметку».
4. Дождитесь завершения очереди. Ошибка одного кадра не останавливает остальные.
5. Откройте кадр со статусом «На проверке».
6. Сравните оригинал и preview, объекты и причины проверки.
7. Нажмите:
   - «Принять» — разрешить экспорт;
   - «Отклонить» — исключить кадр;
   - «Повторить» — снова вызвать агента;
   - «Повторить с детализацией» — выделить до четырёх областей рамкой и уточнить мелкие границы;
   - «Разметить самостоятельно» — создать или исправить контуры мышью без вызова Codex;
   - «Исправить JSON» — вручную изменить класс/координаты и заново пройти серверную валидацию.
8. На главной странице нажмите «Создать ZIP» и скачайте пакет.

Кнопка принятия недоступна, пока в результате есть ошибки валидации.

## Режимы 1X и 2X

- `1X` выбран по умолчанию и всегда ограничен одним вызовом Codex на кадр.
- `2X` делает второй вызов только после разрешённой технической, структурной или
  геометрической проблемы. Хороший первый результат не запускается повторно.
- Тайм-аут и технический сбой также расходуют общий лимит: третий автоматический
  вызов невозможен ни при каких условиях.
- Ручная кнопка «Повторить» начинает новый явно выбранный цикл `1X` или `2X` и
  сохраняет результаты предыдущего цикла.

На странице проверки видны тип каждого вызова, причина, длительность, число
переданных изображений и выбранный результат.

## Детальный проход

Кнопка «Повторить с детализацией» открывает исходный кадр на весь рабочий экран.
Можно протянуть мышью до четырёх прямоугольников; повторный вызов получит оригинал
и эти фрагменты. Если область не выбрана, приложение сформирует фрагменты вокруг
найденных объектов или четыре перекрывающиеся плитки.

Фрагменты только обрезаются: масштабирование, фильтры, повышение контраста,
удаление шума и дорисовка отсутствуют. Приложение проверяет неизменность оригинала,
само переносит координаты `0..1000` с каждого фрагмента на полный кадр, объединяет
дубликаты и передаёт конфликт разных классов оператору. Оригинал плюс до четырёх
фрагментов считаются одним вызовом Codex, но могут расходовать больше входных
токенов.

## Ручная разметка

Кнопка «Разметить самостоятельно» открывает полноэкранный редактор поверх
неизменённого оригинала. Текущая выбранная ревизия используется как начальный
слой; при необходимости можно начать с пустого.

Редактор поддерживает:

- классы «с курицей», «QR-код» и «пустой лоток»;
- четырёхточечные контуры и полигоны из 4–20 вершин;
- выбор и перемещение объекта или отдельной вершины;
- добавление вершины двойным кликом по ребру и удаление вершины;
- смену класса, удаление объекта, очистку слоя;
- undo/redo, масштабирование, панорамирование, подписи и заливку;
- горячие клавиши `1/2/3`, `Enter`, `Escape`, `Delete`, `Ctrl/Cmd+Z`,
  `Ctrl/Cmd+Shift+Z`, `+/-`, `0` и `S`;
- отдельное сохранение черновика и серверную проверку результата.

Черновик переживает обновление страницы и перезапуск приложения, но не становится
доступным для экспорта. «Проверить и сохранить» проверяет диапазоны, площадь,
самопересечения и соседние дубликаты, затем создаёт preview и YOLO label и выбирает
ручную ревизию. После этого оператор отдельно нажимает «Принять». Ручная разметка
не расходует вызовы Codex.

## Где хранятся данные

```text
data/incoming/                    входные пользовательские файлы
data/processing/<item_id>/source контролируемые копии
data/processing/<item_id>/cycles     вызовы `1X/2X`, crops, JSON агента и stderr
data/processing/<item_id>/revisions  черновики и завершённые ручные ревизии
data/exports/                     готовые ZIP
data/legacy/                      копии и отчёты legacy-импорта
logs/labeling.log                 текстовый журнал
queue.sqlite3                     очередь, попытки, запуски, экспорты и ошибки
```

Исходные файлы в `data/incoming` не изменяются и не удаляются. Повторное сканирование того же содержимого не создаёт второе задание.

## Экспорт

ZIP имеет структуру:

```text
images/
labels/
classes.txt
notes.json
manifest.json
```

В `manifest.json` записываются SHA-256, run id, число объектов по классам и исключённые кадры. У изображения и label одинаковый basename. При совпадении исходных имён приложение добавляет короткий безопасный суффикс к обоим именам.

В обучающий YOLO-датасет экспортируются только три последовательных класса:
`0 tray_filled`, `1 qr_code`, `2 tray_empty`. Производственная линия считается
фоном, отдельным объектом не размечается и класс модели под неё не создаётся.
Старые внутренние номера QR и пустого лотка преобразуются автоматически.

Экспорт всегда берёт именно подтверждённую ревизию кадра, а не случайный последний
результат.

CLI-вариант:

```bash
python -m app export
```

## Импорт старой разметки

Исходный ZIP или папка только читаются и никогда не перезаписываются:

```bash
python -m app import-legacy /полный/путь/project-1-at-2026-07-20-11-31-c24623bc.zip
```

Импорт:

- проверяет безопасную структуру ZIP;
- сопоставляет изображения и `.txt` по basename;
- проверяет числа, диапазон `0..1` и число точек;
- сохраняет `0` как `tray_filled`;
- сохраняет существующий `1` как `line`, но не придумывает новые линии;
- сохраняет `2` как `qr_code`;
- добавляет класс `3 — tray_empty` в классы набора;
- создаёт preview и `migration-report.json`;
- направляет каждый импортированный кадр в review.

Старая разметка не различает пустой и заполненный лоток. Поэтому оператор обязан проверить каждый старый объект класса `0` и заменить пустые лотки на класс `3`.

## История разметки и база

Каждый успешный автоматический повтор и каждое ручное исправление создают новую
неизменяемую ревизию. Предыдущие JSON, preview и YOLO label сохраняются. Пока кадр
на проверке, можно выбрать любую его ревизию; кнопка принятия фиксирует выбранную
ревизию как подтверждённую для экспорта.

При первом запуске новой версии старая база обновляется транзакционно. Перед
изменением существующей схемы приложение создаёт проверенную резервную копию в
`queue.sqlite3.backups/`. Кадры, статусы и уже принятые результаты сохраняются.

## CLI

```bash
python -m app doctor
python -m app scan
python -m app process --mode 1x
python -m app process --mode 2x
python -m app export
python -m app import-legacy /path/to/archive.zip

```

`python -m app process --fake` существует только для локального детерминированного smoke-теста. Он не выполняет реальное распознавание и не должен использоваться для производственных кадров.

Обычный набор никогда не вызывает OpenAI:

Реальный тест Codex отключён по умолчанию:

Для полного ручного реального сценария положите одну явно выбранную копию изображения в `data/incoming`, затем выполните:


## Диагностика и типовые ошибки

`python -m app doctor` проверяет ОС и архитектуру, платформенное управление
процессами, версию Python, каталоги, SQLite, конфигурацию, prompt, JSON Schema,
наличие Codex и `codex login status`.

- `Codex CLI не найден` — убедитесь, что команда `codex --version` работает в том же Terminal.
- `Codex не готов` — выполните `codex login`, затем `codex login status`.
- `В очереди нет новых кадров` — сначала выполните сканирование; одинаковый SHA-256 не добавляется повторно.
- `Ответ агента не прошёл структурную проверку` — откройте карточку ошибки и повторите обработку.
- `qr_not_fully_visible` / `qr_occluded` — частичный или закрытый QR запрещён правилами.
- `tray_below_min_visibility` — видимая доля лотка меньше 20%.
- `not_rectangle` — рамка лотка или QR не образует допустимый четырёхточечный прямоугольник.
- `database is locked` — дождитесь завершения текущей операции; приложение использует один worker и `busy_timeout`.

После аварийного завершения задания из `processing` возвращаются в очередь при следующем запуске.

## Настройка

Рабочая конфигурация: `config/app.yaml`. Образец: `config/app.example.yaml`.

Настраиваются лимиты файла/пикселей, timeout и геометрические допуски. В текущей
версии:

- `worker.concurrency` строго равен `1`;
- Codex строго работает в `read-only`;
- `review.required_for_all_mvp_results` строго равен `true`;
- сервер разрешает только `127.0.0.1`/`localhost`.

Глобальная калибровка камеры отключена, потому что кадры могут поступать с разных
камер и ракурсов. `line_use_camera_template` должен оставаться `false`, а
`line_template` — пустым.

## Ограничения качества

Это предразметка, а не замена разметчика. Codex может пропустить объект, неточно восстановить перекрытый лоток или ошибиться в состоянии `empty/filled`. Перед эксплуатацией нужно измерить IoU, recall и точность состояния на отдельном золотом наборе реальных кадров, включая:

- лотки с видимостью 20–30%;
- лотки, перекрытые человеком;
- пустые и слабо заполненные лотки;
- полностью и частично видимые QR-коды;
- разные освещение, размытие и положения линии;
- кадры без целевых объектов.

Структурированный JSON оставлен как дополнительный технический способ исправления;
для обычной работы рекомендуется графический редактор.

## Персональные данные

Кадры с сотрудниками могут содержать персональные данные. Приложение локальное, но выбранное изображение передаётся авторизованному Codex для анализа. До промышленного запуска согласуйте правовое основание, доступ операторов, срок хранения, резервное копирование и правила удаления. Не публикуйте `data/`, `queue.sqlite3`, логи и экспортные ZIP в открытый репозиторий.

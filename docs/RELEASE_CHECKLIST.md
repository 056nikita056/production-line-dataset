# Чек-лист выпуска 1.0.0

Этот документ отделяет автоматическую проверку приложения от реального вызова
Codex. Обычный CI не имеет пользовательской авторизации и никогда не расходует
кредиты.

## Автоматический выпускной прогон

Из чистого клона:

```bash
./scripts/setup.sh
.venv/bin/python -m pytest -q
.venv/bin/python -m app --version
```

На Windows используйте `scripts/setup.ps1` и `.venv\Scripts\python.exe`.

Ожидаемый результат:

- версия `1.0.0`;
- весь набор тестов зелёный;
- один тест с меткой `real_codex` пропущен;
- GitHub Actions зелёный для macOS, Ubuntu и Windows на Python 3.11/3.12;
- `git status --short` пуст;
- `git ls-files data logs queue.sqlite3` показывает только `.gitkeep` в каталогах.

Сквозной тест `tests/test_release_e2e.py` проверяет: сканирование, режим `2X`,
причину второго вызова, ручной черновик, перезапуск, серверную валидацию,
подтверждение, экспорт выбранной ревизии, последовательные классы `0/1/2`,
неизменность оригинала и отсутствие `line`.

## Реальный smoke-тест Codex

Перед каждым прогоном выполните `codex login` и `python -m app doctor`.

macOS/Linux/WSL2:

```bash
RUN_REAL_CODEX_SMOKE=1 .venv/bin/python -m pytest -q -m real_codex tests/test_api_legacy_integration.py::test_real_codex_smoke
```

Windows PowerShell:

```powershell
$env:RUN_REAL_CODEX_SMOKE = "1"
.\.venv\Scripts\python.exe -m pytest -q -m real_codex tests/test_api_legacy_integration.py::test_real_codex_smoke
```

Тест делает ровно один реальный вызов на синтетическом однотонном изображении и
проверяет валидный JSON, размеры кадра и отсутствие `line`.

| Среда | Ответственный | Результат | Дата | Commit |
|---|---|---|---|---|
| macOS | локальный выпуск | успешно | 2026-07-31 | финальное дерево итерации 6 |
| Ubuntu/Debian | владелец Linux-среды | не выполнен | — | — |
| Windows 11 или WSL2 | владелец Windows-среды | не выполнен | — | — |

Релизный тег `v1.0.0` создаётся только когда три строки имеют результат
«успешно» на одном и том же commit и матричный CI этого commit зелёный.

## Ручной интерфейсный прогон

На одном явно выбранном тестовом кадре:

1. просканировать папку и запустить `1X`;
2. открыть кадр на проверке и проверить полноэкранный просмотр;
3. открыть ручной редактор, создать четырёхточечный и произвольный контур;
4. переместить точку, проверить undo/redo, сохранить черновик и обновить страницу;
5. проверить и сохранить разметку, принять кадр и перейти к следующему;
6. создать ZIP и сверить оригинал, preview, label, `classes.txt` и manifest;
7. убедиться, что в ZIP нет `line`, локальных путей, токенов или журналов.

## Приватность

Перед публикацией проверьте:

```bash
git ls-files data logs queue.sqlite3 '*.zip' '*.sqlite3' '*.jpg' '*.jpeg' '*.png'
```

Допустимы только файлы `.gitkeep`. Кадры, база, резервные копии, журналы и ZIP
остаются локальными. Выбранные кадры передаются Codex; оператор должен иметь
правовое основание и соблюдать локальные правила хранения персональных данных.
